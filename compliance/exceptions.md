# Risk-accepted exceptions register

Every policy suppression in `.checkov.yaml`, and every resource tagged `ComplianceException`, needs an entry here. Review each one every 6 months or when its reason stops being true (for example, when the project leaves the free tier).

| ID | Control relaxed | Scope | Reason | Compensating controls | Owner | Next review |
|---|---|---|---|---|---|---|
| EXC-001 | Storage shared-key access disabled | Azure Functions runtime storage account (`*fn`) | The Consumption host and zip deployment use key-based access to their own runtime storage | Account holds no customer data; TLS 1.2 only; no public containers; keys never leave Azure; Azure Policy audits it | Kaya | 2027-03-31 |
| EXC-002 | Customer-managed encryption keys | S3, DynamoDB, CloudWatch Logs, Lambda env, Azure Storage, Cosmos DB | CMKs cost ~$1/key/month, outside the free-tier budget | Provider-managed AES-256 at rest; IAM and Entra ID control access to the data | Kaya | 2027-03-31 |
| EXC-003 | In-cloud cross-region replication | S3, Azure Storage (LRS) | Resilience comes from the second cloud instead of a second region | Azure standby, 6-hourly replication, PITR and continuous backup | Kaya | 2027-03-31 |
| EXC-004 | Authentication on the ordering API; public network on data stores | API Gateway route, Function App, Cosmos DB, web storage | Anonymous customers must be able to order; Consumption plan has no VNet integration | Strict server-side validation, throttling, CORS pinned to 2 origins, Cosmos keyless (Entra ID only), no data reads exposed by the API | Kaya | 2027-03-31 |
| EXC-005 | Web application firewall | CloudFront | AWS WAF is billed per web ACL and rule | AWS Shield Standard, API throttling (10 rps / burst 20), input limits, honeypot field | Kaya | 2027-03-31 |
| EXC-006 | Custom TLS certificate / TLS 1.2 minimum at the edge | CloudFront | The default `*.cloudfront.net` certificate is used until `frostyirie.cr` is delegated | HTTPS redirect, HSTS; add an ACM certificate when the domain is live | Kaya | When domain goes live |
| EXC-007 | Lambda in VPC, DLQ, reserved concurrency, code signing; zone-redundant Functions | Lambda, Azure Functions | Serverless without VPC avoids NAT gateway cost; synchronous API calls return errors to the caller; new accounts cannot reserve concurrency | Least-privilege IAM (PutItem only), deploys only from the approved pipeline, cross-cloud failover | Kaya | 2027-03-31 |
| EXC-008 | 1-year log retention in CloudWatch; geo restriction; S3 event notifications | CloudWatch, CloudFront, S3 | Free-tier log storage; customers are international tourists | CloudTrail kept 1 year in S3 with log file validation; Log Analytics 30 days | Kaya | 2027-03-31 |
| EXC-009 | DynamoDB auto scaling | Both DynamoDB tables | Fixed 5 RCU / 5 WCU per table keeps the stack inside the 25-unit always-free pool; auto scaling could exceed it | CloudWatch throttling metrics; raise capacity through a reviewed PR if the restaurant grows | Kaya | 2027-03-31 |
| EXC-010 | Independent review of changes (segregation of duties) | GitHub pull requests and `prod` deployments | One person builds and operates the platform, and GitHub does not let an author approve their own pull request | Every change still goes through a pull request with all automated gates (tests, secret scan, Checkov, Conftest); the `prod` environment needs an explicit approval click; CloudTrail and the Azure Activity Log record every change; nightly drift detection. Add a second reviewer as soon as one is available | Kaya | 2027-03-31 |
